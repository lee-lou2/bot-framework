# 모델은 격리하고, 위험한 작업은 단일 브로커로 통제하며, 요청은 PostgreSQL에 먼저 커밋합니다.

[English](../why.md) | 한국어

이 설계를 둘러싼 반복적인 "왜?" 질문에 대한 짧은 답변입니다. 정확한 계약은 링크된 명세 문서를 참고하세요.

**한 문장 요약:** AI 모델은 속거나 틀릴 수 있다고 가정하고 키와 호스트 실행 권한을 차단합니다. 권한 검증·사람 승인·감사는 단일 브로커에서 강제하며, 모든 요청은 실행 전에 PostgreSQL에 먼저 커밋합니다.

## 왜 모델만 VM에 격리하나요?

모델은 사용자 메시지와 신뢰할 수 없는 외부 콘텐츠를 함께 읽으므로(프롬프트 인젝션) 가장 신뢰할 수 없는 구성 요소입니다. 로컬 모델 프로세스(`claude-cli`, `codex-cli`, `agy-cli`)를 실행할 때는 해당 프로세스만 시크릿이 전혀 없는 일회용 VM 안에서 실행합니다(프로바이더 키는 호스트 브로커가 보관하고, VM에는 세션 토큰만 전달합니다). 네트워크 이그레스도 브로커 릴레이를 거치는 단일 경로만 허용합니다. 모델이 속더라도 훔칠 키도, 데이터를 빼돌릴 경로도 없습니다.

CLI 하니스나 격리된 워크스페이스 파일 읽기가 필요 없는 에이전트는 직접 API(`anthropic-api`, `openai-api`)를 사용합니다. 격리할 모델 프로세스 자체가 없고, 워커가 업스트림 호출 시에만 프로바이더 키를 첨부하며, 모델에는 호스트 파일시스템이나 셸이 없고, 모든 도구 호출은 여전히 브로커를 거칩니다. ([모델 이미지](model-image.md) · [보안](security.md))

## 왜 봇 전체를 하나의 컨테이너에 넣지 않나요?

게이트웨이, 브로커, 스토어는 Slack 토큰, 데이터베이스 자격 증명, 도구 시크릿을 다룹니다. 모델을 같은 컨테이너에 함께 두면 이 시크릿들과 바로 옆에 놓이게 됩니다. 보안 경계는 봇 바이너리를 어떻게 패키징하거나 배포하는지와 무관하게, 신뢰하는 호스트와 신뢰하지 않는 모델을 분리합니다.

## 왜 미리 띄운 풀 대신 요청마다 새 VM을 쓰나요?

입력, 작업 디렉터리, 세션 토큰은 실행마다 고유하며 VM 생성 시점에 바인딩됩니다. 실행이 끝날 때마다 VM을 폐기하면 다음 실행으로(프로필 간 포함) 상태가 새어 나가지 않습니다. 개발용 Mac 기준 콜드 VM 시작부터 종료까지 1초 미만(마운트·네트워크·방화벽 설정 제외)으로, 일반적인 모델 응답 지연보다 훨씬 짧습니다. 시작 오버헤드가 실제로 병목이 되면 일회용 사전 준비(pre-warmed) 풀을 추후 도입할 수 있습니다(아직 미구현).

## 왜 실행 전에 요청을 PostgreSQL에 먼저 커밋하나요?

요청 수락을 PostgreSQL 커밋으로 정의하면 장애나 재시작이 발생해도 요청이 유실되지 않습니다.

- 중복 전달은 새 실행을 만들지 않고 기존 실행으로 수렴합니다.
- 사람 승인 대기나 자식 위임 중에는 워커가 VM과 리스를 반납하고, 이후 저장된 세션에서 이어서 재개합니다.
- 접수, 큐 상태, 승인, 감사 기록이 같은 트랜잭션 안에서 원자적으로 커밋됩니다.

트레이드오프는 즉각적인 인라인 실행 대신 수락 후 실행하는 2단계 흐름입니다. ([신뢰성](reliability.md))

## 왜 모델 바깥의 브로커 뒤에서 도구를 실행하나요?

도구는 자격 증명이 필요한 실제 작업을 수행하고, 모델은 브로커에 도구 호출을 요청할 뿐입니다. 각 도구는 선언된 시크릿만 전달받고 선언된 이그레스 호스트에만 접속할 수 있으므로, 탈취된 모델이라도 키를 볼 수 없고 도구의 경계를 넘어설 수 없습니다. 브로커는 `호출자 스코프 ∩ 에이전트 상한 ∩ 도구 스코프`를 계산하고, 승인을 강제하며, 감사를 한곳에 기록합니다. 모델이 도구를 직접 실행하면 이 게이트가 우회됩니다. ([MCP 도구](plugins.md))

## 왜 사람 승인을 요구하나요?

비가역적인 부수 효과(외부 메시지 발송, 삭제, 쓰기)에는 대역 외(out-of-band) 사람 확인이 필요합니다. 각 승인은 정확한 인자에 암호학적으로 바인딩되므로 인자가 하나라도 바뀌면 무효화됩니다. 모델은 어떤 작업도 승인할 수 없습니다.

## 왜 모델의 셸, 파일 쓰기, 웹 도구를 비활성화하나요?

공격 표면을 최소화하기 위해 기본으로 비활성화되어 있습니다. `claude-cli` VM에서만 격리 기반 `read`를 명시적으로 선택 허용할 수 있습니다(`codex-cli`, `agy-cli` 및 직접 API 러너는 내장 파일 도구를 노출하지 않습니다). 필요한 기능은 검토를 거친 명시적 도구로 감싸서 제공해야 합니다. ([프로필 명세](profile-spec.md))

## 이 아키텍처가 적합하지 않은 경우

- **로컬 코딩 또는 PC 파일 편집:** 모델이 임의의 코드를 작성·실행하거나 로컬 파일을 직접 수정해야 한다면, 특정 작업만 도구로 감싸거나 프레임워크 밖에서 실행하고 이 프레임워크는 전달과 승인 용도로만 사용하세요.
- **단일 사용자 및 완전 신뢰 입력:** OS 샌드박스와 승인 프롬프트만으로 충분할 수 있습니다. 이 프레임워크는 실제 자격 증명으로 동작하는 다중 사용자 Slack/HTTP 봇을 대상으로 하며, [Anthropic Secure Deployment Guide](https://code.claude.com/docs/en/agent-sdk/secure-deployment)에 따라 모델 실행에 강한 격리를 기본값으로 채택합니다.
- **Apple 외 VM 호스트:** 현재 문서화된 유일한 모델 VM 백엔드는 Apple `container`입니다.
