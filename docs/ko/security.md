# 보안

[English](../security.md) | 한국어

모델은 외부 네트워크 접근이나 서비스 자격 증명 없이 실행됩니다. 모든 도구 호출은 브로커(`Broker::call`)를 통과하고, VM CLI 모델 호출은 브로커 모델 프록시를 거치며, 직접 API·임베딩·메모리 판단기 요청은 호스트가 해석한 키를 아웃바운드 요청 헤더에만 첨부합니다.

## 신뢰 구역

| 신뢰 구역 | 접근 경계 |
|---|---|
| 모델 샌드박스 (`Apple container` VM) | 외부 네트워크와 서비스 자격 증명이 없습니다. 와이어 프로토콜(`Anthropic`, `OpenAiResponses`, `Gemini`)에 고정된 실행별 세션으로만 모델 프록시와 MCP 릴레이에 연결합니다. 읽기 전용 입력(`/bot`)과 시도별 작업 디렉터리(`/work`)를 마운트합니다. 세션 토큰은 환경 변수로만 전달되며 호스트 디스크에는 절대 기록되지 않습니다(`agy-cli`는 권한 강등 후 VM 내부의 RAM 전용 `/tmp/mcp_config.json`으로 템플릿을 확장). 내장 파일 읽기(`/bot` 한정 `Read`)는 `claude-cli`에서만 지원되며 `codex-cli`와 `agy-cli`는 모든 파일 내장 도구를 거부합니다. |
| 직접 모델 API (`worker`) | `anthropic-api` 및 `openai-api` 별칭은 VM이나 릴레이 없이 워커에서 업스트림 API를 직접 호출합니다. 모델은 호스트 파일시스템이나 셸에 전혀 접근하지 못하며(메시지 입력, 텍스트/도구 호출 출력만 수행), 도구는 여전히 `Broker::call`로만 라우팅됩니다. 서비스 키는 적시에 요청 헤더로만 읽히고, 매 `POST` 직전에 활성 리비전을 확인하며, 해당 요청의 키가 포함된 응답은 즉시 폐기하고 연결을 닫습니다. 대상은 설정된 `https` `endpoint`(루프백 IP 리터럴에 한해 `http` 허용)로 제한되며 리다이렉트와 재시도는 비활성화됩니다([아키텍처](architecture.md)). |
| 운영자 도구 서버 (`srt`) | 검토 및 고정된 MCP 서버는 모델 외부의 별도 샌드박스에서 실행됩니다. 브로커는 해당 도구에 선언된 `secrets`만 주입합니다. 서버는 선언된 호스트로 제한된 이그레스 프록시를 통해 외부 API를 직접 호출합니다. |
| 신뢰 호스트 | 게이트웨이, 스케줄러, 워커, 브로커, 스토어, 관리자 UI가 인증·실행·상태를 담당합니다. 단일 `SecretStore`가 역할별로 논리적 이름을 해석합니다: 게이트웨이는 어댑터·비공개 접수 자격 증명을, 워커는 직접 모델 API·`embeddings`·`memory_judge` 키를, 브로커는 VM 모델 프록시·`embeddings`·도구별 자격 증명을, Admin 관측성은 OTLP/Sentry 자격 증명을 읽습니다. |

## 모델 VM 경계

- **네트워크 경계.** Apple container의 `--internal`(`hostOnly`) 네트워크는 인터넷 송신을 차단하지만, VM 내부 필터링이 없으면 같은 네트워크의 형제 VM이나 호스트 게이트웨이의 다른 열린 포트에는 도달할 수 있습니다. 브로커에 도달하는 요청은 세션 토큰으로 인증합니다.
- **신뢰 초기화 (`bot-init`).** 다이제스트가 고정된 이미지는 `/usr/local/bin/bot-init`(POSIX `sh`)을 root로 시작하여, 호스트에서 검증된 숫자 IPv4 주소와 포트를 재검증하고, 릴레이 TCP와 established 응답만 허용하는 `nftables` 규칙(IPv6 포함 나머지 모두 기본 차단)을 적용한 뒤 규칙을 다시 읽어 검증합니다. 이후 `setpriv`로 UID:GID `10001:10001`, 보조 그룹 없음, Linux capability 0개, `no_new_privs`로 권한을 낮춘 다음 고정된 CLI(`claude`, `codex`, `agy`)를 실행합니다. 초기화에 실패하면 모델을 시작하지 않고 `vm_init_failed`로 종료합니다.
- **검증.** Apple container Linux 6.18.15(`aarch64`)와 Claude Code 2.1.331에서 검증되었습니다. 모델이 릴레이를 통해 가짜 업스트림과 통신하는 동안 다른 게이트웨이 포트, 피어 VM, 외부 주소는 차단되었으며, 네 가지 초기화 capability 중 하나라도 제거하면 모델 실행 전 `vm_init_failed`로 종료되었습니다. 이미지나 커널을 변경할 때마다 검증을 다시 실행하세요([모델 VM 이미지](model-image.md)). v2.0 모델 이미지는 `nftables`를 필수로 요구하며, 검증할 수 없는 규칙이나 권한 강등 실패 시 실행을 중단합니다.
- **파일시스템과 CLI 노출면.** 루트 파일시스템과 `/bot`은 읽기 전용이며, 호스트는 비루트 모델이 복구용 세션 로그를 기록할 수 있도록 시도별 `/work`를 준비합니다. 텔레메트리, 자동 업데이트, 내장 도구는 기본적으로 비활성화됩니다(고정된 Claude 버전에서는 에이전트가 요청한 `Read`만 허용). 호스트에서 마운트되는 것은 시도별 입력과 `/work`뿐입니다.
- **앵커 VM.** 워커는 자격 증명과 마운트가 없는 앵커 VM을 전용 네트워크에 연결하여 `hostOnly` 속성과 게이트웨이 IP를 검증하고, 릴레이를 정확히 해당 IP에만 바인딩합니다(와일드카드, 루프백, 기타 주소 거부). 앵커 또는 IP 검증에 실패하면 모델 실행을 중단합니다. 종료 시 워커는 앵커를 제거하기 전에 릴레이를 먼저 닫습니다.

## 도구 샌드박스, 이그레스 및 시크릿

- **로컬 도구 샌드박스 (`srt`).** 운영자 MCP 도구는 `@anthropic-ai/sandbox-runtime`(`srt`) `0.0.83` 아래에서 실행됩니다. `deny_read`가 홈, SSH, 키체인 및 다른 프로필 경로를 차단하며, 도구에 선언된 `secrets`, 일반 설정, 호스트가 관리하는 프록시/콜백 주소만 주입합니다. 실제 도구 프로세스로 로컬 macOS와 Linux CI에서 격리를 검증하며, `srt` 누락, 버전 불일치, 격리 검증 실패 시 실행을 거부합니다. 공유 `/tmp/claude`는 읽기/쓰기가 차단됩니다(macOS에서는 `srt` 설정으로, `srt`가 이를 다시 마운트하는 Linux에서는 `bwrap` 래퍼가 호스트 디렉터리를 수정하지 않고 호출마다 빈 읽기 전용 `tmpfs`를 오버레이). 각 호출은 전용 작업 디렉터리에서 실행됩니다.
- **이그레스와 사설 매핑.** 도구는 직접 인터넷, DNS, 로컬 네트워크 우회 경로가 없습니다. 이그레스 프록시는 모든 요청, 해석된 IP 주소, 리다이렉트 전반에서 정확한 `host:port`를 강제합니다. 로컬 도구는 도구 `egress` ∩ 프로필 상한에서 이미 허용된 호스트와 포트에 한해 `host.json`의 `private_egress` 프로필별 `host:port -> IP:port` 매핑으로 사설 엔드포인트에 접근할 수 있습니다. 자격 증명 값을 숨긴다고 해서 그 자격 증명이 가진 권한까지 사라지지는 않으므로 도구별로 스코프, 이그레스, 승인을 제한해야 합니다.
- **SecretStore와 백엔드.** macOS 운영 호스트에서는 `BOT_SECRETS=keychain`을 사용하세요(생략 시 개발용 `env`로 폴백). SOPS/age를 사용할 때는 복호화 개인 키를 암호화 파일과 분리해 보호해야 합니다. 단기 데이터베이스 자격 증명이 필요하면 외부 OpenBao(MPL-2.0) 어댑터를 추가하세요. Vault는 BUSL-1.1 라이선스 때문에 기본 권장 대상이 아닙니다([SOPS](https://getsops.io/docs/) · [OpenBao DB secrets](https://openbao.org/docs/secrets/databases/) · [OpenBao 라이선스](https://github.com/openbao/openbao/blob/main/LICENSE) · [Vault 라이선스](https://github.com/hashicorp/vault/blob/main/LICENSE)).
- **프로필 범위 격리.** `SecretStore`는 호스트가 검증한 `profile`과 구분자 없는 `name`을 별도로 받아 `bot/<profile>/<name>`만 읽습니다. 호출자는 프로필이나 전체 키를 전달할 수 없으며 전역 폴백도 없습니다. 게이트웨이는 바인딩의 프로필 아래에서 자격 증명을 해석하고, 모델 프로바이더는 운영자의 프로필별 허용 목록에서만 선택됩니다.
- **단일 운영자 신뢰 경계.** 각 호스트는 한 명의 운영자가 관리합니다. 프로필 파일은 신뢰된 설정이며, 프로필 내 도구 자격 증명 할당은 운영자가 정의합니다. 모델은 프로필 파일이나 호스트 셸에 접근할 수 없고, 메모리 쓰기는 PostgreSQL로만 기록됩니다. 실시간 스킬/MCP 편집(`skill.*`, `mcp.*`)은 단일 브로커 게이트(`crates/bot-broker/src/service/manage.rs`)를 통과하며, 고정 리비전과 현재 리비전 모두에서 `super_admins`와 스코프를 검사합니다(그 외 호출은 `not_super_admin`으로 차단). SOPS 파일(`BOT_SECRETS=sops:<file>`)은 도구 샌드박스 `deny_read`에 유지되며, `mcp.add`로 저장한 시크릿은 즉시 마스킹 목록에 추가되고 암호화된 SOPS/키체인에만 저장됩니다(원시 `secret_value`와 `secret_values`는 승인 카드에서도 마스킹됨). 다중 운영자 호스트는 v2.0 범위 밖입니다.
- **신뢰할 수 없는 회상 메모리.** 워커는 구성원이 편집 가능한 회상 메모리에 출처를 태깅하고, 본문을 사용자 입력 내 신뢰할 수 없는 참고 자료로만 주입합니다.

## 실행 흐름 예시 — 캘린더 일정 삭제

1. **게이트웨이 인증.** CLI는 로컬 OS 사용자를, Slack은 인증된 Socket Mode 세션과 앱·팀 ID를, HTTP는 등록된 issuer·audience·만료 시각을 검증합니다. 호스트 설정이 구성원과 응답 대화를 매핑하고 미등록 호출자를 거부하며 진입점별 속도 제한을 적용합니다.
2. **브로커 인가.** 모든 도구 호출은 **요청자 권한 ∩ 에이전트 상한 ∩ 도구 스코프**(상위 위임 스코프와 프로필 정책으로 추가 제한)를 계산하고 주체별 속도 및 동시성 제한을 적용합니다. 정적 `cron`은 프로필의 서비스 주체로 평가되며, 채팅으로 생성된 스케줄과 후속 작업은 생성자의 신원과 권한 상한을 유지합니다.
3. **위험도와 승인 바인딩.** `read`는 조회, `write`는 변경, `irreversible`은 되돌릴 수 없는 작업입니다. `irreversible` 호출과 정책으로 지정된 `write` 호출은 실행(run), 세대(generation), 호출 ID, 프로필, 요청자, 승인자, 위험 등급, 정책 리비전, 도구 리비전, 검증된 전체 `args`의 정규 JSON(RFC 8785) SHA-256, 만료 시각, 일회용 nonce에 바인딩된 사람 승인이 필요합니다. 승인 카드는 동일한 브로커 검증 인자에서 대상과 변경 내용을 렌더링합니다.
4. **사람 검증과 커밋.** Slack 버튼은 인증된 Socket Mode 세션(앱, 팀, 클릭한 사용자)을 검증하고, 관리자 API는 운영자 인증과 CSRF 토큰을 검증합니다. Slack 채널 기원 승인은 다른 채널 멤버에게 도구 이름과 인자가 노출되지 않도록 지정 승인자의 1:1 DM으로만 전체 카드를 전달하고 원 채널에는 고정 안내만 게시합니다. 클릭자는 사전 지정된 승인자(기본값: 요청자, 정적 서비스 스케줄: 프로필이 지정한 사람, 명시적 대상 스케줄 생성/전달: 스케줄 소유자)와 일치해야 합니다. 모델과 서비스 주체는 절대 승인할 수 없습니다. 실행 직전에 현재 정책을 다시 확인한 뒤 승인 소비, 호출 시작, 감사를 원자적으로 커밋합니다. 철회, 거부, 만료 시 실행이 차단되며 위험도 상승, 규칙 변경, 세대 증가, 인자 변경은 기존 승인을 무효화하고 새 카드를 요구합니다. 모델 IPC와 도구 채널은 모든 메시지에서 실행과 세대에 바인딩됩니다.

## 보장 범위와 경계

- **모델 프록시 필터링.** 선언된 요청 필드와 클라이언트 도구만 전달하며 프로바이더 측 웹 검색, 코드 실행, 원격 MCP 서버, 컨테이너 호출은 거부합니다. 스트리밍 검사는 이벤트와 디코딩된 청크를 확인하여, 청크 끝부분이 알려진 키 접두사와 3바이트 이상 일치하면 다음 청크까지 해당 접미사를 보류하고 전체 키가 완성되면 폐기합니다. 열린 스트림은 세션 토큰 철회와 주기적 클레임 확인 시 종료됩니다.
- **정책 강제 경계.** 스킬 문서, 모델 출력, 이벤트는 권한을 부여하지 못하며 강제는 브로커 도구 호출 경계에서 이루어집니다. 운영자 도구는 선언된 자격 증명과 호스트 범위 내의 신뢰 코드이므로 `read` 도구가 읽기만 수행하도록 보장하려면 설치 검토와 읽기 전용 자격 증명에 의존합니다. 각 승인은 `args`의 정확한 대상과 수량을 고정하므로 다른 대상을 다루려면 별도의 승인된 호출이 필요합니다.
- **외부 송신 `destination` 규칙.** 외부로 전송하는 변경 도구는 `destination: reply`(인증된 원 대화/스레드에 고정) 또는 `destination: {recipient: args.to, content: args.message}`를 선언하며, 전송하지 않는 변경 도구는 생략합니다. 원 스레드 내 응답은 기존 게시 권한을 사용합니다. 호스트 허용 서비스라 하더라도 다른 채널·사람·이메일·웹훅·외부 계정으로 전송하면 `irreversible`로 격상되며, 브로커는 승인 카드에 정확한 수신자·내용·첨부파일을 표시하고 고정하며 둘 중 하나라도 해석할 수 없으면 전송을 차단합니다.
- **비공개 메모리 오염.** `private` 메모리를 읽으면 데이터가 모델에 도달하기 전에 실행 플래그가 영구 저장됩니다. 그 시점부터 `external` 도구(`read` 검색 포함)는 매 호출마다 정확한 송신 인자에 바인딩된 사람 승인이 필요합니다. 이 플래그는 재개와 위임에도 유지되고, 자식 결과에서 부모로 병합되며, 같은 요청 트리 내 동시 실행 간에도 공유됩니다. 더 세밀한 데이터 분류는 v2.0 범위 밖입니다.
- **출력 및 시크릿 검사.** 시크릿 값은 모델 샌드박스에 절대 들어가지 않으며, 신뢰 도구도 자격 증명을 반환해서는 안 됩니다. 브로커는 모델로 반환하기 전에 결과 크기, 구조, 노출 여부를 검증합니다(악의적 운영자 코드의 은닉 유출은 탐지할 수 없음). 도구 출력과 이펙트 영수증은 *해당 호출*이 사용한 자격 증명과 토큰 형태에 대해서만 검사하며, 관측성/관리자 응답에 쓰이는 프로필 간 이력 마스킹 목록과는 비교하지 않아 한 프로필이 다른 프로필에 등록된 시크릿을 탐색할 수 없습니다. 응답과 첨부파일은 전송 전 원 대상과 현재 게시 권한을 다시 확인합니다. 메모리는 프로필·에이전트·소유자별로 격리됩니다.
- **원격(Streamable HTTP) MCP 서버.** 브로커가 `srt` 외부에서 직접 연결하므로 동등한 통제를 별도로 강제합니다.
  - 대상은 도구 `egress` ∩ 프로필 상한에 엄격히 포함되는 단일 설정 `host:port`여야 하며, 매 연결마다 모든 IP를 해석·검사하여 사설 IP가 하나라도 있으면 거부합니다.
  - 평문 `http`는 루프백 IPv4 리터럴(숫자로 끝나는 호스트는 정규 형식)에만 허용되며 리다이렉트는 절대 따르지 않습니다.
  - 매 요청 직전에 활성 리비전을 재확인해 오래된 프로세스가 철회된 엔드포인트에 접근하지 못하게 합니다.
  - Bearer 토큰은 이름으로 읽어 Authorization 헤더에만 넣으며, 해당 토큰이 포함된 응답은 폐기합니다.
  - 쓰기 호출은 요청 ID가 일치하는 `2xx` 응답만 수용하고(그 외는 결과 불명으로 보류), 연결 종료만으로 원격 종료를 증명하지 못하며, 원격 콜백 채널이 없으므로 `effects: true`는 지원하지 않습니다.
  - 호출 전 도구 정의(이름, 설명, 입력 스키마)는 승인된 `tools.lock.yaml` 해시와 일치해야 합니다. `tools/list`는 신뢰할 수 없으므로 `bot mcp sync`가 자격 증명 노출과 스키마를 검증하고 모든 페이지를 받은 뒤에만 락파일을 기록합니다.
- **비공개 메모리 공유 및 쓰기.** `memory.share`, `memory.save`, `memory.forget`은 인증된 사람 소유자의 본인 DM 또는 CLI에서만 허용됩니다. `memory.share`는 해당 단일 ID를 읽어 전체 범위와 본문을 소유자에게 표시하며(전체 본문이 카드에 들어가지 않으면 진행 거부), `memory.save`는 소유자 전용 `private` 항목만 기록하면서 소유자당 활성 500건 쿼터, 정확/근접 중복 생략, 비파괴 `supersedes`, 선택적 `policy.approve` 게이트를 강제합니다(미승인 텍스트는 외부 임베딩 엔드포인트로 전송하지 않음). 다른 사람에게 보이는 승인 목록, 실행 상세, 감사 기록에서는 본문을 제외합니다. `host.json`에 `embeddings`나 `memory_judge`가 설정된 경우 아웃바운드 요청도 직접 모델 API와 동일한 `https`/루프백 전용 엔드포인트 검증, 이중 활성 리비전 검사, 프로필 범위 `SecretStore` 조회, 응답 유출 스캔을 따릅니다. `memory_judge`는 인증된 사람의 1:1 DM/CLI 원문 메시지와 본인 회상 비공개 기억만 검사하며(비신뢰 도구 출력·채널 메시지 제외), 로컬 규칙과 `contains_secret`으로 자격 증명을 차단하고, 모델이 이미 `memory.save`/`memory.forget`을 실행한 턴은 건너뛰며, 본인 소유 `private` 행만 변경합니다.
- **감사 체인.** 호스트 전체에 걸친 단일 해시 체인이 모든 상태 변경과 같은 트랜잭션에서 시퀀스 번호, 이전 해시, 주체, 대상, 입력 다이제스트, 판정을 커밋합니다. 운영자는 전체 체인을 재계산해 위변조 여부를 검증할 수 있습니다(DB 전체를 재작성할 수 있는 DB 슈퍼유저로부터는 방어하지 않음). 로그와 오류는 허용 목록 메타데이터만 출력합니다.
- **관측성과 민감 DM.** OTLP 트레이스는 기본적으로 메타데이터만 기록합니다. 프롬프트와 도구 결과 수집은 외부 데이터 유출에 해당하므로 프로필별 명시적 옵트인, 시크릿 마스킹, 프로필이 지정한 컬렉터가 필요합니다(미설정 또는 사용 불가 시 생략). 트레이스, 로그(`admin.logs`), 이슈(`admin.issues`) 엔드포인트는 `https://`를 바로 허용하며(Langfuse, LangSmith, 원격 OTLP, Sentry 등), 평문 `http://`는 루프백/사설 주소에 한해 옵트인 없이 허용됩니다(그 외 평문 URL은 해당 섹션에 `remote: true`가 있어야 시작 가능). 호스트 수준 관측성 자격 증명은 `host.json`의 리터럴 값 대신 SecretStore 이름(기본 `bot/host/<name>` 또는 지정 프로필)을 참조하며, 로그/이슈 본문과 태그는 내보내기 전 라이브 `Redactor`를 거칩니다. 승인 nonce와 민감 DM 원시 페이로드는 콘텐츠 수집과 이슈 태그에서 제외됩니다. 민감 DM은 기본적으로 비공개 처리되며, 일치한 트리거가 `private_pass: true`를 설정하고 해당 도구가 유효한 빈 PASS를 반환하면 원본 본문과 첨부파일 참조가 일반 실행으로 전환됩니다(이후 일반 대화 정책이 모델 입력과 트레이스를 규율하며, 비공개 원장과 접수 감사는 원시 페이로드를 저장하지 않음)([관리자 API 및 관측성](admin.md)).
- **사전 승인 정적 크론(`preapproved`)과 `human_approval`.** `preapproved` 정적 크론은 승인 ID를 프로필, 트리거, 소스, 주체, 스코프, 도구, 설치 리비전, 고정 인자, 허용 `(operation, target)` 쌍, 상한, 대상 매핑의 핑거프린트에 바인딩합니다. 호출 시작 커밋과 새로운 외부 쓰기 권한 부여 모두에서 동일한 PG 락 아래 활성 세트, 승인 ID, 일시정지 세대, 허용 쌍, 일일 UTC 상한을 재검증하면서 사용량과 감사를 원자적으로 기록합니다. 권한 부여는 해당 승인 회차의 직접 호출에만 적용되며 모델, 위임, 깨우기, 다른 트리거, 이벤트 본문에는 절대 상속되지 않습니다. 브로커는 선언된 `(operation, target)` 쌍의 인가와 횟수를 보장하며, 실제 수신자 바인딩은 대상 범위가 제한된 자격 증명이나 검토·고정된 어댑터에 의존합니다. **한계:** 대상을 바꾸려면 새 자격 증명 이름과 새 승인이 필요하며, 같은 이름 아래 시크릿 값을 회전하는 것은 탐지되지 않습니다(SecretStore 쓰기 권한이 있는 운영자만 수행 가능). 지정된 사람의 메시지나 리액션(`human_approval`)은 해당 이벤트의 진입점 인증 행위자가 현재 리비전과 고정 리비전 모두에서 승인자일 때만 승인 단계 1회를 대체하며, 독립 요구사항(비공개 회상 후 확인, 비공개, 소유자 전용)은 절대 우회하지 못합니다.
- **향후 강화 옵션.** 역할별 OS UID 및 DB 계정, 분산 mTLS, 외부 서명 체크포인트, 고위험 승인용 단계별 재인증, 작업 카탈로그를 갖춘 브로커 호스팅 커넥터.
