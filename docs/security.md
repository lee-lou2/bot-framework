# 모델은 외부망과 서비스 자격 없이 실행되고, 브로커를 통해 모델 제공자와 도구를 이용한다.

| 신뢰 구역 | 접근 범위 |
|---|---|
| 모델 샌드박스 · Apple container VM | 외부 네트워크·서비스 자격 없이 실행한다. 모델 프록시와 MCP 중계는 현재 실행 전용 세션으로만 연결한다. VM에는 읽기 전용 입력과 실행별 작업 공간만 제공한다. 세션 토큰은 환경변수로만 전달하고 모델이 읽을 수 있는 어떤 파일에도 쓰지 않는다. 내장 Read를 켜도 Claude Code가 읽는 곳은 입력 폴더(`/bot`)뿐이며 쓰기 공간·시스템 파일·`/proc`은 거절한다(실제 VM에서 확인). |
| 운영자 도구 서버 · srt | 검토하고 고정한 MCP 서버를 모델 밖 별도 샌드박스에서 실행한다. 브로커는 현재 도구에 선언한 비밀만 환경으로 넣는다. 서버가 외부 API를 직접 호출한다. 네트워크는 선언한 호스트로 가는 egress 프록시만 허용한다. |
| 신뢰 호스트 | Gateway·scheduler·worker·broker·store와 관리 UI가 인증, 실행, 상태를 맡는다. SecretStore 하나가 논리 이름을 값으로 해석한다. 게이트웨이는 자기 어댑터 자격을 직접 받고 브로커는 도구별 자격을 받는다. |

**현재 확인한 망 경계.** Apple container의 `--internal` 망(`hostOnly`)은 외부 연결을 차단한다. 같은 망에 있는 이웃 VM과 호스트 게이트웨이의 다른 열린 포트에는 연결할 수 있다. 세션 토큰은 브로커에 도착한 요청을 인증한다.

**모델 실행 조건.** 다이제스트로 고정한 이미지의 POSIX sh 진입점 `/usr/local/bin/bot-init`이 root로 먼저 실행된다. 호스트가 검증한 숫자 IPv4와 포트를 다시 검사하고 nftables로 그 릴레이 TCP 연결과 응답만 허용한다. 다른 목적지와 IPv6는 기본 차단한다. init은 적용된 규칙을 확인한 뒤 `setpriv`로 UID:GID `10001:10001`, 보조 그룹과 Linux capability 없음, `no_new_privs` 상태에서 Claude를 시작한다. 초기화 실패는 비정상 종료로 처리하고 모델을 시작하지 않는다.

Apple container의 Linux 6.18.15(aarch64)에서 Claude Code 2.1.331 이미지로 확인했다. 모델은 릴레이로 가짜 상류와 대화했고, 같은 게이트웨이의 다른 열린 포트·이웃 VM·외부 주소 접근은 차단됐다. init 권한 네 개 중 하나라도 빠지면 모델을 시작하기 전에 `vm_init_failed`로 종료했다. 배포할 이미지나 커널을 바꾸면 같은 점검을 다시 실행한다. [모델 이미지 빌드와 실환경 점검](model-image.md)

v2.0 모델 이미지는 nftables가 필요하다. 규칙 적용이나 권한 강등을 확인할 수 없으면 init이 종료되고 모델 실행도 중단된다.

모델 VM의 루트와 입력은 읽기 전용이다. 호스트는 시도마다 전용 작업 폴더를 준비해 `/work`로 제공한다. 비root 모델이 세션을 저장하고 호스트가 그 기록을 읽어 복구할 수 있어야 한다. CLI의 원격 측정과 자동 갱신은 끈다. 내장 도구도 기본으로 끄고, 고정한 Claude 버전에서는 에이전트가 요청한 `Read`만 켤 수 있다. 호스트에서 VM에 마운트하는 범위는 해당 시도의 입력과 작업 폴더다.

워커는 사용자 마운트와 자격이 없는 닻 VM을 전용망에 붙인다. 전용망의 hostOnly 속성과 게이트웨이 IP를 확인한 뒤에만 그 IP에 릴레이를 연다. 전체 인터페이스·루프백·다른 IP로의 바인드는 거절한다. 닻이나 주소를 확인할 수 없으면 모델 실행을 중지한다. 워커는 종료할 때 자신의 릴레이를 먼저 닫고 닻을 정리한다.

운영자 MCP 도구는 `@anthropic-ai/sandbox-runtime`(`srt`) 0.0.83에서 실행한다. 홈·SSH·키체인·다른 프로필 경로를 읽기 금지 목록에 두고 도구별로 선언한 비밀·일반 설정과 호스트가 관리하는 프록시·콜백 주소를 제공한다. macOS 로컬과 Linux CI에서 실제 도구 프로세스로 격리를 검사한다. srt 부재·판본 불일치·격리 실패 시 실행을 거절한다. 도구 프로세스는 srt의 공용 임시 경로 `/tmp/claude`를 읽거나 쓸 수 없다. 실행마다 전용 작업 폴더를 쓴다.

도구에는 직접 인터넷·DNS·로컬 네트워크 우회 경로를 열지 않는다. 프록시는 요청마다 정확한 호스트와 포트를 확인하고 주소 해석 결과와 리디렉션에도 같은 제한을 적용한다. 자격 값을 모델에서 숨겨도 그 자격으로 행사할 수 있는 권한은 남는다. 도구마다 스코프·접속 목적지·승인 대상을 제한한다.

macOS 운영 환경에서는 `BOT_SECRETS=keychain`을 권장한다. 설정을 생략하면 개발용 `env`를 쓴다. SOPS/age를 쓰면 복호화 개인 키를 암호화 파일과 별도로 보호한다. 단기 DB 계정을 발급해야 할 때는 외부 OpenBao(MPL-2.0) 어댑터를 추가할 수 있다. Vault는 BUSL-1.1 배포 조건 때문에 기본 선택으로 권장하지 않는다. [SOPS](https://getsops.io/docs/) · [OpenBao DB 자격](https://openbao.org/docs/secrets/databases/) · [OpenBao 라이선스](https://github.com/openbao/openbao/blob/main/LICENSE) · [Vault 라이선스](https://github.com/hashicorp/vault/blob/main/LICENSE)

SecretStore는 호스트가 확인한 프로필과 경로 구분자 없는 이름을 분리해 받아 `bot/<profile>/<name>`만 읽는다. 호출자가 프로필이나 전체 키를 넘길 수 없고 전역 이름 폴백도 없다. 게이트웨이는 설정된 바인딩의 프로필로 자격을 조회한다. 모델 제공자는 운영자가 프로필마다 허용한 목록에서만 선택한다.

한 호스트는 한 운영자가 관리한다. 프로필 파일은 그 운영자의 신뢰된 설정이며 같은 프로필 안의 도구 자격 배분도 운영자가 정한다. 모델은 프로필을 읽기 전용으로 보고 기억은 DB에만 쓴다. 여러 운영자를 한 호스트에 수용하는 배치는 v2.0 범위 밖이며 향후 호스트 차원의 자격 상한을 둘 수 있다.

## 예시 — 일정 하나 삭제

1. Gateway가 요청을 인증한다. CLI는 로컬 OS 사용자, Slack은 인증된 Socket Mode 세션과 앱·팀 식별자, HTTP는 등록한 인증 발급자·대상·만료를 확인한다. 서버 설정으로 멤버와 회신 대화를 결정한다. 미등록 사용자는 거절하고 입구별 요청량을 제한한다.
2. 브로커가 모든 도구 호출에서 **요청자 권한 ∩ 에이전트 상한 ∩ 도구 스코프**를 계산한다. 부모의 위임 범위와 프로필 정책도 상한이다. 필요한 권한 전체와 주체별 속도·동시성 한도를 검사한다. 정적 cron은 프로필에 등록한 서비스 주체로 검사한다. 대화에서 만든 예약과 후속 확인은 만든 사람의 신원과 권한 상한을 유지한다.
3. read는 조회, write는 변경, irreversible은 되돌릴 수 없는 작업이다. irreversible과 정책 지정 write는 추가 승인이 필수다. 일정 삭제는 run·세대·호출 ID·프로필·요청자·승인자·위험 등급·정책 판본·도구 판본·검증된 전체 인자의 SHA-256 해시(RFC 8785 정규 JSON)·만료·일회용 nonce에 묶는다. 승인 화면은 브로커가 같은 인자로 렌더링한 대상과 변경 내용을 보여 준다.
4. Slack 버튼은 인증된 Socket Mode 세션에서 앱·팀과 클릭한 사용자 신원을 확인한다. 관리 API는 운영자 인증과 CSRF 토큰을 확인한다. 클릭한 사람이 미리 지정된 승인자와 일치해야 한다. 기본 승인자는 요청자다. 정적 서비스 예약은 프로필이 지정한 사람에게, 명시 목적지 예약의 생성·발송은 예약 소유자에게 승인을 받는다. 모델과 서비스 주체는 승인할 수 없다. 승인 소비·호출 시작·감사를 함께 커밋한다. 실행 직전 현재 정책으로 다시 판정한다. 철회·거절·만료는 실행을 막고, 위험 등급 상향·승인 조건 변경·세대 교체·인자 변경은 종전 승인을 무효화한다. 새 조건을 표시하고 다시 승인받는다. 모델 IPC와 도구 채널은 run·세대에 묶어 각 메시지에서 검사한다.

## 보장 범위

모델 프록시는 선언된 요청 필드와 클라이언트 도구만 상류로 전달한다. 제공자 측 웹 검색·코드 실행, 원격 MCP 서버와 컨테이너 호출은 거절한다. 스트리밍 응답은 이벤트와 디코딩한 조각을 검사한다. 끝이 알려진 키의 앞부분과 3바이트 이상 일치하면 뒤 조각을 기다리고, 완전한 키가 되면 보류했던 부분도 폐기한다. 열린 스트림은 세션 토큰 회수와 주기적인 claim 확인으로 닫힌다.

스킬 문서·모델 출력·이벤트는 권한을 부여할 수 없다. 브로커는 도구 호출 경계에서 집행한다. 운영자 도구는 선언한 자격과 호스트 안에서 실제 작업을 수행하는 신뢰 코드다. 읽기라고 선언한 서버가 실제로 읽기만 하는지는 설치 검토와 읽기 전용 자격에 의존한다. 승인 한 건이 허용하는 실제 변경 대상·수량을 입력으로 확정한다. 실행 중 대상이 달라지면 별도 도구 호출로 승인받는다.

쓰기 도구의 destination은 전송 목적지를 나타낸다. 전송 기능이 있는 도구는 `destination: reply`(인증된 원래 대화·스레드 고정) 또는 `destination: {recipient: args.to, content: args.message}`처럼 수신자와 내용의 경로를 선언한다. 전송 기능이 없는 변경 도구는 생략한다. 원래 대화 회신은 기존 게시 권한으로 가능하다. 다른 채널·사람·메일·웹훅·외부 계정은 호스트가 허용한 서비스라도 irreversible로 올린다. 브로커가 정확한 수신자·내용·첨부를 승인 카드에 표시하고 고정한다. 목적지나 내용을 결정할 수 없으면 발송하지 않는다. private 기억이 한 건이라도 조회되면 모델에 전달하기 전에 브로커가 해당 실행의 플래그를 저장한다. 이때부터 검색을 포함한 external 도구는 read라도 호출마다 정확한 전송 인자에 묶인 사람 승인이 필요하다. 재개·위임 시 플래그를 유지하고 자식 결과가 부모로 돌아갈 때도 합친다. 동시 실행은 같은 요청 트리의 플래그를 공유한다. 그 외 데이터 등급 추적은 v2.0 범위 밖이다.

비밀 값은 모델 샌드박스에 주입하지 않는다. 신뢰된 도구는 자격을 결과로 돌려주지 않아야 한다. 브로커는 크기·결과 형식과 알려진 자격 값 노출을 검사한 뒤 모델에 전달한다. 악성 운영자 코드의 은닉 유출까지 탐지할 수는 없다. 회신·첨부 전에는 원래 목적지와 현재 게시 권한을 검사한다. 기억은 프로필·에이전트·소유자로 구분한다.

private 기억 공유는 소유자의 DM·CLI에서 요청한다. 브로커는 해당 ID 한 건을 읽고 소유자에게 공유 범위와 본문 전체를 보여준다. 카드에 본문 전체를 표시할 수 없으면 공유를 진행하지 않는다. 다른 사람이 보는 승인 목록·실행 상세·감사에는 본문을 싣지 않는다.

감사는 호스트 전체에 해시 체인 하나를 유지한다. 상태 변경과 같은 트랜잭션에 순번·이전 해시·주체·대상·입력 지문·판정을 기록한다. 운영자만 전체 체인을 다시 계산해 변조 여부를 검증한다. DB 전체를 다시 쓸 수 있는 관리자까지 검증하는 보장은 없다. 로그와 오류는 허용된 메타데이터만 남긴다.

도구 결과·효과 영수증을 검사할 때는 그 호출에 쓰인 자격 값과 토큰 모양을 대조한다. 관측·관리 응답의 가림 목록에는 여러 프로필의 과거 자격 값도 들어 있다. 이 목록을 도구 출력의 허용 여부에 사용하면 한 프로필이 다른 프로필의 값이 등록됐는지 추측할 수 있어 검사 범위를 호출 단위로 제한한다.

OTLP 추적은 기본으로 메타데이터만 기록한다. 프롬프트와 도구 결과를 수집기로 보내는 것은 외부 데이터 전송이므로 운영자가 프로필별로 명시적으로 켜야 한다. 내용 기록을 켠 프로필은 알려진 비밀 값을 가린 뒤 그 프로필에 지정한 수집기로만 보낸다. 수집기를 지정하지 않았거나 사용할 수 없으면 내용을 보내지 않는다. 수집기 주소는 평문 http라 루프백·사설 주소만 받고, 그 밖의 주소(이름 포함)는 운영자가 프로필마다 `remote`를 명시해야 시작한다. 민감 DM 원문과 승인용 일회값은 이 설정을 켜도 수집하지 않는다. [관리·관측](admin.md)

향후 강화 옵션은 역할별 OS UID·DB 계정, 분산 mTLS, 외부 서명 체크포인트, 고위험 승인 재인증, 모든 외부 연산을 대행하는 브로커 커넥터·operation 카탈로그다.

## 근거

- 서비스 자격은 에이전트 밖 프록시에 두고, stdio 도구에는 그 프로세스가 쓸 자격만 전달한다. [Anthropic 보안 배포 지침](https://code.claude.com/docs/en/agent-sdk/secure-deployment) · [MCP 전송별 인증 규약](https://modelcontextprotocol.io/specification/latest/basic/authorization)
- 도구의 권한을 줄이고 되돌리기 어려운 작업은 모델 밖에서 사람이 승인한다. [OWASP 에이전트 보안 지침](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html) · [OWASP 과도한 실행 권한](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)
- 비공개 데이터·신뢰할 수 없는 입력·외부 전송이 한 실행에 모이면 정보 유출 위험이 커진다. 이 설계에서 private 기억을 읽은 뒤 외부 전송에 승인을 요구하는 이유다. [Simon Willison의 위험 분석](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/) · [Meta의 에이전트 보안 원칙](https://ai.meta.com/blog/practical-ai-agent-security/)
